# Student Marks Portal with Firebase and GitHub Login

A beginner-friendly student marks portal built with HTML, CSS, JavaScript, Firebase Authentication, Cloud Firestore, and Firebase Hosting.

Students sign in using GitHub, submit their registration number, and wait for administrator approval. Approved students can view their marks category by category. Administrators can approve students, create assessment categories, enter marks, generate class reports, and upload marks from CSV files.

## Main features

- GitHub-only signup and sign-in
- Firebase UID used as each user's Firestore document ID
- Student registration-number form
- Administrator approval for new accounts
- Separate student and administrator dashboards
- Any number of assessment categories, such as Quiz, Assignment, Midterm, Final, Lab, Project, or Presentation
- Any number of marks entries inside each category
- Category tabs and category totals for students
- Category-wise and overall reports for administrators
- CSV report downloads
- CSV templates for bulk marks entry
- Firestore security rules preventing students from changing marks or approving themselves
- Responsive layout for desktop and mobile devices

## How the application works

```text
Student signs in with GitHub
             ↓
Student enters a registration number
             ↓
Account is saved with approved: false
             ↓
Administrator reviews and approves the account
             ↓
Student can view category-wise marks
```

An administrator is a Firebase user whose UID also exists as a document inside the `admins` Firestore collection.

## Requirements

Before starting, install:

- [Git](https://git-scm.com/downloads)
- [Node.js](https://nodejs.org/) (LTS version recommended)
- A [GitHub account](https://github.com/)
- A [Firebase account](https://console.firebase.google.com/)

The application can use Firebase's no-cost Spark plan for Authentication, Firestore, and static Hosting within the plan limits.

## 1. Fork and download the repository

On GitHub, click **Fork** to create a copy under your account.

Clone your fork:

```bash
git clone https://github.com/YOUR_GITHUB_USERNAME/YOUR_REPOSITORY_NAME.git
cd YOUR_REPOSITORY_NAME
```

Replace `YOUR_GITHUB_USERNAME` and `YOUR_REPOSITORY_NAME` with your real GitHub username and repository name.

## 2. Create a Firebase project

1. Open the [Firebase Console](https://console.firebase.google.com/).
2. Click **Create a project**.
3. Enter a project name.
4. Complete the project-creation steps.
5. Open **Project settings > General**.
6. Scroll to **Your apps** and select the Web icon (`</>`).
7. Enter an app nickname and click **Register app**.

Firebase displays a configuration object. Keep this page open because its values are required in the next step.

## 3. Configure `firebase-config.js`

Open:

```text
public/firebase-config.js
```

Replace its values with the configuration shown under:

```text
Firebase Console > Project settings > General > Your apps > SDK setup and configuration > Config
```

The file must keep the `export` keyword:

```javascript
export const firebaseConfig = {
  apiKey: "YOUR_API_KEY",
  authDomain: "YOUR_PROJECT_ID.firebaseapp.com",
  projectId: "YOUR_PROJECT_ID",
  storageBucket: "YOUR_STORAGE_BUCKET",
  messagingSenderId: "YOUR_MESSAGING_SENDER_ID",
  appId: "YOUR_APP_ID",
  measurementId: "YOUR_MEASUREMENT_ID"
};
```

The Firebase Web API key and project identifiers are public frontend configuration, not administrator credentials. Never place a GitHub Client Secret, Firebase service-account file, private key, or personal access token in this file.

## 4. Create the Firestore database

1. Open your project in Firebase Console.
2. Select **Firestore Database**.
3. Click **Create database**.
4. Choose a database location.
5. Finish creating the database.

The repository includes `firestore.rules`. These rules will be deployed later with the Firebase CLI.

## 5. Enable GitHub Authentication

First create a GitHub OAuth App:

1. Open GitHub.
2. Go to **Settings > Developer settings > OAuth Apps**.
3. Click **New OAuth App**.
4. Fill the form using the following pattern:

```text
Application name:
Your Student Marks Portal

Homepage URL:
https://YOUR_PROJECT_ID.web.app

Application description:
A student marks portal using Firebase and GitHub authentication.

Authorization callback URL:
https://YOUR_PROJECT_ID.firebaseapp.com/__/auth/handler
```

Leave **Enable Device Flow** unchecked.

After registering the OAuth App:

1. Copy its **Client ID**.
2. Click **Generate a new client secret**.
3. Copy the Client Secret immediately.
4. Open **Firebase Console > Authentication > Sign-in method**.
5. Select **GitHub**.
6. Enable the provider.
7. Paste the GitHub Client ID and Client Secret.
8. Confirm that the callback URL shown by Firebase matches the callback URL configured on GitHub.
9. Click **Save**.

The GitHub Client Secret belongs only in Firebase Console. Never add it to this repository.

## 6. Configure authorized domains

Open:

```text
Firebase Console > Authentication > Settings > Authorized domains
```

Confirm these domains exist:

```text
YOUR_PROJECT_ID.web.app
YOUR_PROJECT_ID.firebaseapp.com
```

Add your custom domain later if you use one. Enter domain names without `https://`.

## 7. Change the registration-number list

The allowed student registration numbers are generated in:

```text
public/app.js
```

Find:

```javascript
const allowedRegistrations = Array.from(
  { length: 29 },
  (_, i) => `2022-BSE-${String(49 + i).padStart(3, "0")}`
);
```

This generates `2022-BSE-049` through `2022-BSE-077`.

For another class, replace it with your own list:

```javascript
const allowedRegistrations = [
  "2025-BSE-001",
  "2025-BSE-002",
  "2025-BSE-003"
];
```

## 8. Install and configure Firebase CLI

Install Firebase CLI:

```bash
npm install -g firebase-tools
```

Log in:

```bash
firebase login
```

Select your Firebase project:

```bash
firebase use --add
```

Choose your project and assign the alias `default`.

Alternatively, copy `.firebaserc.example` to `.firebaserc` and replace `YOUR_PROJECT_ID`:

```json
{
  "projects": {
    "default": "YOUR_PROJECT_ID"
  }
}
```

If you run `firebase init`, select only:

```text
Firestore: Configure security rules and indexes files
Hosting: Set up deployments for static web apps
```

Use `public` as the Hosting directory. If Firebase asks to overwrite `public/index.html`, `firestore.rules`, or `firebase.json`, answer **No** so it does not replace the files supplied by this project.

## 9. Run the application locally

From the project root, start the Firebase local server:

```bash
firebase serve --only hosting
```

Open the local URL shown by Firebase CLI, normally:

```text
http://localhost:5000
```

If GitHub login is required during local testing, confirm `localhost` is listed in Firebase Authentication authorized domains. Do not open `public/index.html` directly as a `file://` URL because browser module and authentication behavior may fail.

Stop the server with `Ctrl+C`.

## 10. Deploy to Firebase Hosting

Deploy the website and Firestore rules:

```bash
firebase deploy --only hosting,firestore:rules
```

Firebase prints a Hosting URL similar to:

```text
https://YOUR_PROJECT_ID.web.app
```

Whenever you change only HTML, CSS, or JavaScript, deploy Hosting again:

```bash
firebase deploy --only hosting
```

Whenever you change `firestore.rules`, deploy the rules:

```bash
firebase deploy --only firestore:rules
```

## 11. Create the first administrator

Administrator access is not granted by email address. It is granted using a Firebase UID.

1. Visit the deployed website.
2. Sign in with the GitHub account that should become administrator.
3. Open **Firebase Console > Authentication > Users**.
4. Copy that account's **User UID**.
5. Open **Firestore Database > Data**.
6. Create a collection named `admins`.
7. Create a document whose document ID is exactly the copied UID.
8. Add an optional string field: `role` = `admin`.
9. Sign out and sign in again.

Example:

```text
admins
└── FIREBASE_ADMIN_UID
    └── role: "admin"
```

Do not add normal student UIDs to the `admins` collection.

## 12. Student registration and approval

After first login, a student enters a registration number. Firestore creates:

```text
users/{firebaseUid}
├── registration_number: "2022-BSE-049"
├── approved: false
├── first_name: "Student"
├── last_name: "Name"
├── user_name: "github-username"
├── email: "student@example.com"
└── created_at: timestamp
```

The student sees an approval-pending page. In the admin dashboard, select the student, change the account status to **Approved**, and save.

## 13. Add categories and marks

In the admin dashboard:

1. Select a student.
2. Click **Add category**.
3. Enter a category name, such as `Quiz`, `Assignment`, `Midterm`, `Final`, or `Project`.
4. Click **Add entry**.
5. Enter an entry name, obtained marks, and total marks.
6. Add more entries or categories as required.
7. Click **Save user and marks**.

Example Firestore marks structure:

```text
marks
└── categories
    ├── 0
    │   ├── name: "Quiz"
    │   └── items
    │       ├── 0: { name: "Quiz 1", obtained: 8, total: 10 }
    │       └── 1: { name: "Quiz 2", obtained: 9, total: 10 }
    └── 1
        ├── name: "Project"
        └── items
            └── 0: { name: "Semester Project", obtained: 18, total: 20 }
```

## 14. Reports and CSV marks upload

The administrator can generate:

- A category-wise report containing individual entries and category totals
- An overall report containing one obtained-total column per category
- A downloadable CSV report

For bulk marks entry:

1. Select **Category-wise marks**.
2. Select a category.
3. Generate the report.
4. Click **Download template**.
5. Open the CSV in Excel or another spreadsheet application.
6. Enter obtained marks without changing the header names or registration numbers.
7. Save the file as CSV.
8. Choose the completed CSV in the admin panel.
9. Click **Upload marks**.

The application validates registration numbers, missing cells, numeric values, negative marks, and scores exceeding the configured maximum before updating Firestore.

## Security notes

- Firebase web configuration is public and can be committed.
- The GitHub OAuth Client Secret must remain only in Firebase Console.
- Never commit a Firebase service-account JSON file.
- Never allow students to write to the `admins` collection.
- Keep `firestore.rules` deployed and under source control.
- Consider enabling Firebase App Check before using the portal in production.
- Review administrator accounts periodically and remove UIDs that no longer require access.

## Common problems

### Firebase welcome page appears

Firebase replaced `public/index.html`. Restore this repository's `public/index.html`, then deploy Hosting again.

### Missing or insufficient permissions

Deploy the included security rules:

```bash
firebase deploy --only firestore:rules
```

Also confirm the Firebase CLI is targeting the correct project with `firebase use`.

### GitHub button does nothing

Open the browser developer console. Confirm `public/firebase-config.js` exports `firebaseConfig`, GitHub Authentication is enabled, the domains are authorized, and the OAuth callback URL ends with `/__/auth/handler`.

### User does not see the admin panel

Confirm the user's exact Firebase UID exists as a document ID under `admins`, then sign out and sign in again.

### Changes do not appear after deployment

Force-refresh the browser with `Ctrl+F5` or open the website in a private window.
